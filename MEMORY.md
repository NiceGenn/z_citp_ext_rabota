## Дебаг v2.4.1 (2026-07-05)

Аудит исходников выявил и исправил дефекты (детали — в `docs/ЧТО_НОВОГО.md`):
- **HIGH:** `xlsx-parser.js` читал ячейки по позиции — пропуск пустой ячейки сдвигал
  колонки и молча портил базу. Теперь маппинг по букве столбца из атрибута `r`.
  Проверено: строка с пропущенным столбцом D больше не смещает роль/систему.
- **MEDIUM:** `docx-generator.js` удалял все строки после заголовка (стирал контент
  пользовательских шаблонов). Теперь удаляются только строки-заглушки той же
  структуры. Проверено на реальном шаблоне: заглушки [12,13] удаляются, лишняя
  строка-примечание сохраняется; поведение штатного шаблона не изменилось.
- **MEDIUM:** `x509-parser.js` не понимал PEM-`.cer`. Добавлен авто-детект PEM→DER.
  Проверено: PEM и DER одного сертификата парсятся идентично.
- Мелочи: inlineStr в xlsx, эвристика даты, регистр `.cer`, permission `windows`,
  мёртвый `.replace`.

Верификация выполнена прогоном реальных модулей в Node (linkedom + jszip) и на
декодированном встроенном шаблоне; браузерный E2E не проводился.

## Решения (репозиторий / структура)

- **2026-07-05 — Схема «исходники → сборка».** Единый источник правды —
  `sources/citp-zayavka/`. Релизы собираются только `tools/build-release.sh`
  в `releases/`; руками `releases/` не редактируем.
- **Имя `citp-zayavka`.** Исходно предлагалось `theme/gos30`, но это был пример;
  проект — расширение, а не тема оформления. Slug соответствует `name`/`short_name`
  из manifest. Схема `sources/<slug>/` оставляет место под будущие варианты.
- **Релизный zip — только чистое расширение.** Без .md-доков и dev-утилит
  (`gen-icons.js`). `manifest.json` — в корне архива (требование загрузки в браузер).
- **В `releases/` храним все версии** (история релизов в репозитории).
- **Версия — единый источник в `manifest.json`.** Скрипт сборки берёт её оттуда,
  код расширения — тоже (не дублируется, начиная с v2.1.0).
- **`gen-icons.js` → `tools/`.** Это генератор иконок (dev-время), не часть
  поставки; в релиз не попадает.

## Архитектурные факты (из рефакторинга v2.0)

- Монолит разбит на ES-модули в `js/` (`state`, `x509-parser`, `xlsx-parser`,
  `matcher`, `docx-generator`); `popup.js` — только UI.
- **DOCX-генерация** ищет места вставки по ключевым словам («Роль субъекта»,
  «Серийный номер», шаблон даты `«___» 20__ г.`), а не по номерам строк — шаблон
  можно свободно переоформлять выше таблицы.
- **Сопоставление ФИО** — нечёткий поиск (расстояние Левенштейна): приоритет фамилии,
  имя/отчество по инициалам, прощает до ~2 опечаток в длинных фамилиях.
- Философия: максимальная автономность, работа в браузере клиента, ноль тяжёлых
  сторонних зависимостей (только вендорный JSZip).

## Требования к DOCX-шаблону (чтобы генератор находил места вставки)

- Шапка таблицы содержит «Роль субъекта» и «Серийный номер» (или «ФИО»).
- Есть строка с датой в виде `«___»` / `20__`.
- Таблица присутствует в документе.

## Формат базы АЦК (`.xlsx`)

Лист «АЦК», 5 столбцов: `№ п/п | Логин ЦИТП | Субъект ЭП | Роль субъекта | Система`.
Роль (D): Руководитель/Бухгалтер. Система (E): АЦК-Финансы/АЦК-Планирования
(краткие «Финансы»/«Планирование» нормализуются). Один логин может иметь несколько
строк (разные системы) — объединяются в одну строку заявки при совпадении роли.
